普段は要件定義から実装・運用まで担当するフルスタックエンジニアとして働いている。趣味はゲームと動画視聴で、以前はゲーム開発もしていた。

そんな中、「AIを使って何か将来の収入につながることを始めたい」と思い立ち、AIエージェント(Claude Code)に相談してみることにした。今回はその最初の一歩の記録。

## 最初に出てきた選択肢

最初にAIに相談すると、大きく4つの方向性が返ってきた。

- ゲーム開発×AI(AIアシストのインディーゲーム開発、開発者向けAIツール)
- コンテンツ発信(技術系YouTube/Zenn/note、ゲーム実況+エンジニア視点解説)
- SaaS・受託(業務課題向けAI SaaS、AIエージェント構築の受託)
- 掛け合わせ型(発信しながら製品も作る二段構え)

正直、最初は選択肢の多さに面食らった。

## 「軽い作業量で、一人で完結したい」という条件を伝えてみた

自分の希望を整理すると、

- 本格的な副業というより、空いた時間にできる程度にしたい
- 受託や会社とのやり取りは避けたい(仕事感が強くなるため)
- 一人で完結できるものが良い

という条件だった。これを伝えると、候補は一気に絞り込まれた。受託・コンサル系は除外され、代わりに「技術情報発信」と「作って終わりの軽量プロダクト(プロンプト集・テンプレート販売)」が中心候補として残った。

## 競合の多さという壁

ただ、ここで一つ引っかかった。AIで自動的に記事を書いて投稿する、というやり方自体は既に多くの人がやっている。同じような自動化をしている人は山ほどいるはずで、そのまま量産しても埋もれるだけではないか、という懸念があった。

この点をAIに相談したところ、「AIが構造的に真似しにくいものを差別化軸にする」という方向性が提案された。具体的には、

- 検索結果の要約ではなく、実際に自分が体験したことをネタにする
- ニッチを絞り込む(汎用的な「AI×開発」ではなく、自分にしかない掛け合わせに寄せる)
- 完全自動化しすぎず、自分の一言を残す
- 継続すること自体が差別化になる

という話だった。そして、今まさにこの「初めてAIエージェントを使ってみた過程」自体が、他人には書けない一次情報のコンテンツになる、という提案を受けた。この記事はその実践例にあたる。

## ここまでで分かったこと

AIエージェントを初めて触ってみて感じたのは、テーマ出しから構成、下書きまでを一気に任せられる速さと、逆に「差別化」や「何を書くか」という判断は結局人間側の材料(実体験や条件)がないと薄くなる、というバランス感覚だった。

次は、この記事の投稿までの技術的な流れ(GitHub・Zenn連携、定期実行の設定)を整えていく予定。

初めてAIエージェントを使ってみて感じたのは、思った以上に使い勝手が良いということだった。自分の経験だけでは補いきれない部分は素直にAIに投げ、壁打ちを重ねることで、一人でもより質の高いものを作っていけそうだという感触を得られたのが今回の一番の収穫だった。

振り返ると、今回一番効いたのは「軽い作業量で」「一人で完結したい」「受託のようなやり取りは避けたい」といった自分の条件をはっきり伝えたことだったように思う。丸投げにせず、自分の判断基準を先に言葉にするほど、返ってくる提案の解像度も上がっていく感覚があった。この記事自体も、その延長線上で生まれた一次情報のコンテンツということになる。
